# M0 — Research, reverse engineering, and online architecture

## Objective

Establish verified PAL SMG1, toolchain, Dolphin integration, and multiplayer architecture facts before implementing runtime hooks.

## Verified research

- Local original and AllReds DOL hashes/layouts/diff were reproduced by Rust analysis tools; see `docs/references/dol-diff.md`.
- Petari is a WIP SMG1 decompilation (CC0-1.0) with user-supplied DOL and C++ build pipeline. Bussun's loader is described as USA-only and requires CodeWarrior PPC EABI; its license is unclear. SMG2 symbols are not SMG1 mappings.
- Rust is primary for host/portable code; Wii bare-metal PPC ABI/linking has not been proven.
- The supplied PAL DOL SHA-1 matches Petari's `config/RMGP01/build.sha1`; Petari includes PAL-specific symbols/splits. Its source translation-unit ranges are usable research anchors, but runtime object pointers/member offsets still require disassembly and live validation.
- PAL Rev 0 identity is registered in the Rust catalog using the verified DOL SHA-256. The entry intentionally contains no hooks.
- A fresh-process Dolphin 2609a sampled comparison and ignored Rust live test pass. A complete previous section comparison also matched, but current routine validation samples to avoid thousands of unnecessary reads.
- Product architecture is online-only, one Dolphin instance per player. Dolphin NetPlay and local split-screen are explicitly excluded.
- BSMSO documents one Dolphin instance/player, a game module plus launcher RAM mailbox, and a server relaying player state. Its repository declares GPL-3.0, while MultiGalaxy1 is MIT; no code is copied and license compatibility must be reviewed before reuse.
- SM64CoopDX documents game-level sync APIs with client/server networking; its engine implementation is not portable to Galaxy.
- The requested Zone of Games Russian archive remains unavailable/uninspected; see `docs/references/russian-patch.md`.

## Functional requirements

- Preserve/reproduce the reference DOL analysis without modifying inputs.
- Bound GDB operations with deadlines, progress, and short samples by default; keep complete executable scans opt-in.
- Map Petari's PAL Mario actor call path against the exact PAL executable without promoting translation-unit ranges to function or object addresses.
- Select only exact verified PAL revision maps; reject unknown executable hashes and hook bytes.
- Design four-player lobby/identity/state sync, server authority, local prediction, and client-local language support.
- Define a Dolphin bridge that reads the local player and renders remote characters through verified game operations.
- Require a two-Dolphin runtime proof before claiming online multiplayer.

## Technical design

Rust workspace owns patch analysis, launcher, protocol/networking, deterministic data types, and tests. A narrow versioned IPC bridge connects the launcher to verified injected hooks; minimal PPC/C++ may be required. Do not infer APIs or addresses from unrelated games or the AllReds binary.

## Dependencies

Rust/Cargo; exact legal PAL files; verified game symbols/revision; Dolphin/source and bridge investigation; PPC disassembly/injection toolchain; controller integration; two Dolphin instances for runtime validation.

## Risks

Engine singleton assumptions; game actor instantiation/rendering; Dolphin integration limitations; networking latency/reconciliation; shared campaign state; locale assets influencing gameplay; incompatible reference license; unavailable Russian archive; Rust Wii ABI/linker feasibility.

## Acceptance criteria

- Reference hashes and DOL section/diff report reproduce.
- Safe Rust analysis tests pass and do not write inputs.
- Research records source, confidence, licensing, and unresolved issues.
- Exact PAL identity is recognized by the tool; unknown hashes remain rejected and the registered identity entry does not imply any verified hook.
- Online-only architecture is documented, including authority, bridge, locales, and two-instance proof.
- No multiplayer, localization, or runtime hook claim exceeds evidence.

## Testing strategy

Run workspace Rust tests and compare the two local reference DOLs. Runtime tests require two separate Dolphin processes and a legitimate PAL game build; current M0 does not claim game boot or multiplayer behavior.
